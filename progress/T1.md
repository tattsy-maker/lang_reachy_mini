# T1 — Camera capture module — progress notes

Status: **done** (2026-08-31), with the real-camera E2E **blocked on a
permissions one-liner** (below). File-source path fully tested: 7 passed,
1 skip (`tests/run.sh t1`).

## What landed

- **[face/camera.py](../face/camera.py)** — `Camera(source, fps=2.0)` with
  three sources behind one `frames()` generator: a live V4L2 index
  (sleep-paced to the cap, buffer drained so frames are current), a video
  file (the clip's *timeline* is subsampled to the cap with no wall-clock
  sleeping — tests stay fast and deterministic), and an image directory
  (all images, no pacing — snapshots are discrete). The generator releases
  the capture on any exit path; `closed` is asserted by test.
- **[face/check_camera.py](../face/check_camera.py)** — lists `/dev/video*`
  with sysfs names, grabs and saves one frame.
- **Tests** in `tests/t1/`: shape/dtype, rate-cap arithmetic (90-frame
  15 fps clip → exactly 12 frames at 2 fps), image-dir count, clean
  shutdown on `break` and via context manager, error paths, plus a
  `robot`-marked non-black-frame test for the real camera.

## Decision: where face dependencies live

## Blocked: real-camera frame grab

The Reachy camera is `/dev/video0` (`/dev/video1` is its metadata node —
don't read frames from it). Both are `root:video` with an ACL that adds
only `gdm`, and **altha is not in the `video` group**, so every open fails
— `check_camera.py` output (2026-08-31, daemon not running, so the device
was otherwise free):

```
device candidates:
  /dev/video0: Reachy Mini Camera: Reachy Mini
  /dev/video1: Reachy Mini Camera: Reachy Mini
trying /dev/video0 ...
  could not open 0 — ... check ... the 'video' group ...
```

Passwordless sudo is not available to the agent. **The fix needs the user
once:**

```bash
sudo usermod -aG video altha
```

then a fresh login shell (or `sg video -c ...`), then:

```bash
cd face && ../voice/.venv/bin/python check_camera.py   # should save a frame
tests/run.sh t1                                        # robot test un-skips
```

This is the third instance of CLAUDE.md's group-membership trap
(`dialout` → serial, `audio` → sound, now `video` → camera); worth adding
`video` to the CLAUDE.md setup line once confirmed.

## Learnings

1. **Rate cap semantics differ by source on purpose.** A live device must
   sleep (and keep reading, or V4L2 hands you stale buffered frames); a
   file must *not* sleep, or a 6 s fixture costs 45 s of test time. Same
   API, two implementations, both asserted.
2. **The daemon question is moot when the daemon is down.** With
   `reachy-mini-daemon` not running, the camera needs no
   `set_media_released` handoff at all — the handoff only matters for the
   integrated T10 flow, where the voice agent already performs it.
