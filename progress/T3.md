## Design decisions (the parts T4/T9/T10 should rely on)

1. **`append_session` owns the bookkeeping.** One call prepends the notes
   entry *and* bumps `sessions` / `last_seen`, so the T4
   `save_session_notes` tool cannot half-update a learner. Entries are
   `## YYYY-MM-DD — Session N` headings; the body is whatever prose the
   tutor wrote (the four-section format is the prompt's job, not the
   store's — the store stays dumb on purpose).
2. **`read_notes(id, max_sessions=N)`** exists precisely for the T4
   briefing ("the most recent sessions"): newest-first storage makes
   truncation a prefix cut.
3. **Collisions:** folder ids are ASCII slugs (`maría` → `maria`), with
   `-2`/`-3` suffixes; the spoken display name lives in the profile and
   `find_by_name` matches it case-insensitively — two booth Marias get two
   folders and both stay greetable.
4. **Corrupt profiles are quarantined, not destroyed:** `load` warns and
   returns None, `list` skips them, and — deliberately — `wipe_guests`
   never deletes what it cannot read, because an unreadable profile might
   be family. Asserted by test.
