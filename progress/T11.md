## 2026-08-31 (later): smoke test green on metal

After the `video` usermod and the Gemini key: the booth smoke test now
runs the real thing — serve + agent + camera session mode came up
(**9 s with the vendor daemon warm** — the ~40 s figure is cold-start
only), and SIGINT tore it down cleanly (robot home, media back, no
orphans). Two script bugs found and fixed by making the test honest:

1. **Append-only logs faked readiness** — `grep` over `serve.log` /
   `run.log` matched a *previous* run's "ready" lines (the exact trap the
   runbook documents). The script now only reads lines written after
   launch.
2. **The subshell ate the shutdown signal** — the agent ran inside
   `( cd voice; python … ) &`, so the trap's `kill -INT` hit the subshell
   and never reached python; orphaned serve/agent processes survived the
   first failing test run. The agent is now exec'd directly and shutdown
   stops real PIDs with bounded patience (SIGINT, never SIGKILL first).

## 2026-09-02: first in-person rehearsal (cloud mode)

Run with the user at the robot, agent logs watched live. Verdict from
the family: **Gemini Live's voice is the one to ship**; the local Kokoro
voice was judged poor (partly a bug, see 1 below, but the preference
held after the fix). Two real visitors enrolled by voice and got notes.

What worked in person, on the real robot and camera:

- Stranger flow → consent → `enroll_new_learner` from 4 live camera
  snapshots (Alex/Italian, then John Maritime/French) → lesson with
  nods, shakes, wiggles, head turns → goodbye → well-formed notes.
- Language switch mid-session persisted to the profile
  (`set_target_language`, new this day).
- Volume by voice (`set_volume`, new): "quieter" → 50%, "louder" → 100%,
  confirmed on the ALSA mixer.
- Cloud latency felt instant; tool calls reliable with the discipline
  addendum.

Bugs found and fixed on the spot (all in `voice/`):

1. **English spoken by the Russian voice (local mode).** Whisper
   mis-detected room noise as Russian, the router switched the voice to
   Piper's `ru` (impossible before T5), and English replies came out as
   Russian phonemes. Tutor mode now never lets the voice follow
   detection; the model picks voices via span tags with English as the
   untagged default (spec §6's "target from profile, not detection").
2. **"I can't see you."** The base prompt still denied having a camera;
   with a face source it now says it recognizes faces and nothing else.
3. **Cloud mode unresponsive to a live microphone.** pipecat's Gemini
   service drops mic audio until it has an initial context; every
   `--say` test supplied one, a real session never did. The agent now
   kicks off the conversation itself in cloud mode (the robot greets
   first).
4. **"Russian is not among the languages I can teach."** Gemini
   over-read "never switch the lesson language"; there was also no tool
   to change a learner's language. Added `set_target_language`, an
   explicit "you can teach every language you can speak" line for cloud,
   and a wider language map (Swedish was asked for and refused).
5. Transcripts were logged at DEBUG (invisible in rehearsal); now INFO
   as `heard (xx): ...`.
6. Volume: mixer defaulted to 90%; now 100% at booth start, plus the
   tool.

Gaps found, not yet fixed (→ T12):

- **Cloud mode is one visitor per launch.** The session runner's
  watch/walk-away/reset loop only works with the local stack: Gemini
  keeps conversation state server-side, ignores later local context
  swaps, and its system instruction is fixed at connect. In cloud mode
  the agent looks for a face once at startup; if nobody is in frame in
  those ~3 s it starts in stranger mode (happened once; the comeback
  test as Alex was therefore not completed).
- Notes should follow the *current* profile language after a switch
  (John's notes said "next time: French" after switching to Russian).
- Two guest profiles (`learners/alex`, `learners/john-maritime`) remain
  on disk from the rehearsal; `python tutor/wipe_guests.py` clears them.

Operational lessons: launch long-lived processes detached (a plain `&`
from a tool shell dies with the shell); `sg video -c` is needed only in
shells that predate the usermod; grep booth logs from this run's offset,
never the whole append-only file.

## 2026-09-04: booth mic — USB when present, the robot's own otherwise

The desk mic is a Jieli "USB Composite Device" (card 2; PyAudio names it
`USB Composite Device: Audio (hw:2,0)`, mono, input only). The rule is
now in code rather than a knob someone has to remember at the venue:
`agent.py --mic-device` (default `USB Composite Device`, a comma list
tried in order) takes the first matching input device and falls back to
the `--audio-device` mic, the robot's. `start_booth.sh` passes it
(`BOOTH_MIC_DEVICE`) and prints which mic it expects from
`/proc/asound/cards`; the agent log's `audio: mic ...` line is the
authority. The speaker is always the robot's.

The catch that made this more than a name lookup: the USB mic only
opens at 48 kHz and the robot's mic only at 16 kHz (PortAudio: `Invalid
sample rate` for the other). pipecat's `LocalAudioTransport` opens the
mic at the pipeline rate, so it could not open the USB mic at all.
`ResamplingAudioInput` (in `agent.py`) opens at the device's rate and
resamples each callback chunk with a streaming soxr resampler to
16 kHz, so the VAD, Whisper, Gemini Live and the voice-print collector
see exactly what they were measured on.

Measured on the box, 2 s through the real transport into a pipeline:

| mic | opened at | frames | audio | RMS |
|---|---|---|---|---|
| USB Composite Device (index 5) | 48 kHz → 16 kHz | 64 × ~980 B | 1.96 s | 597 |
| Reachy Mini Audio (index 4), USB name absent | 16 kHz | 99 × 640 B | 1.98 s | 1530 |

PortAudio hands the USB mic's callbacks in ~30 ms chunks whatever the
20 ms request; nothing downstream cares. Tests in
`tests/t11/test_audio_devices.py`: the selection table (runs anywhere)
and a real open at the probed rate (audio + models markers).
