## Two real findings (both fixed, both worth remembering)

1. **Multi-turn text injection needs two paths.** The FIRST `--say` must
   go through the user aggregator: it seeds the service's context object
   (without which Gemini's tool calls are refused with "Function calls
   are not supported without a context object") and triggers the initial
   inference. But Gemini Live manages conversation state server-side and
   deliberately ignores later local context updates — so a second `--say`
   through the aggregator simply vanished (the first two-turn run's
   goodbye got no response at all). Later turns now use the service's own
   text-injection path (`_create_single_response`: client content + the
   Gemini-3 "won't infer without realtime input" nudge). Real microphone
   audio is unaffected — it always streams straight to the service.
2. **Gemini needs the tool-discipline reminder Claude never did.** With
   the identical briefing, Gemini would *say* goodbye but skip the
   `save_session_notes` call. A cloud-only system-prompt addendum ("your
   tools are real actions… emit the call in that same turn") made it
   reliable. This is precisely the spec's "prompt work doesn't
   automatically carry over" risk, confirmed and patched.
