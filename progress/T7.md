## The honest numbers (span survival: how much of the embedded foreign
phrase came back recognizably; 100 = verbatim)

| Pair | Unprimed | Primed | Best config | Verdict (spec's terms) |
|---|---|---|---|---|
| en+es | 86.0% | **96.2%** | primed | seamless locally |
| en+it | **92.0%** | 79.5% | unprimed | seamless locally |
| en+ru | 61.6% | **87.5%** | primed | good locally (priming is transformative) |
| en+fr | **82.4%** | 51.5% | unprimed | decent locally; cloud mode for the showpiece |
| en+pt | **73.6%** | 40.0% | unprimed | **cloud mode recommended** |
| en+zh | **68.8%** | 56.2% | unprimed | **cloud mode recommended** |

Two mechanisms behind the numbers, both visible in the report:

1. **Unprimed Whisper *translates* Russian.** "я хочу есть" came back as
   "I want to eat"; "библиотека" as "Biblio teca". With the bilingual
   prompt it keeps the Cyrillic verbatim — +26 points, the single
   biggest effect measured.
2. **Priming triggers Whisper's hallucination mode for fr/pt/it/zh** —
   repetition loops ("My favorite phrase is! My favorite phrase is…"),
   empty transcripts, stray Arabic. That is why priming is now a
   **measured per-pair policy** (`PRIMING_HELPS = {"es", "ru"}` in
   multilingual.py), not a blanket setting. The gate keeps measuring the
   raw effect so the policy can be re-derived when the model changes.
